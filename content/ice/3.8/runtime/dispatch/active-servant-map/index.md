Each object adapter maintains an _active servant map_ (ASM): a table that associates each servant you add to it with an
identity and a [facet](../../facets). [The Dispatch Pipeline](../dispatch-pipeline) describes how an object adapter uses
its ASM to dispatch a request.

![The client proxy contains endpoint 212.8.7.33 and identity Joe. The request reaches the server object adapter, whose active servant map associates Fred, Joe, and Carl with servants. The highlighted Joe entry selects the matching servant.](/images/ice/3.8/active-servant-map/binding-request-to-servant.svg)

_Dispatching a request to the correct servant._

## Adding and Removing Servants

You add a servant to the ASM with [`add`](api:Ice/ObjectAdapter.add) or
[`addWithUUID`](api:Ice/ObjectAdapter.addWithUUID), and remove it with [`remove`](api:Ice/ObjectAdapter.remove).
[`addFacet`](api:Ice/ObjectAdapter.addFacet), [`addFacetWithUUID`](api:Ice/ObjectAdapter.addFacetWithUUID) and
[`removeFacet`](api:Ice/ObjectAdapter.removeFacet) do the same for a facet other than the default facet. See
[ObjectAdapter](api:Ice/ObjectAdapter) in the API reference for these methods.

Each identity and facet has at most one servant, but you can add the same servant with several identities. Removing a
servant does not affect the dispatches in progress in this servant. Destroying the
[object adapter](../object-adapter-activation-and-deactivation) empties its ASM.

{% iflang langs="cpp,csharp,java,js,swift" %}

A servant in the ASM usually implements a skeleton generated by the Slice compiler, but it can be any
[dispatcher](../dispatcher-api).

{% /iflang %}
